# 系统思考与因果回路（system_loops）

## 一句话定义

把问题看作系统结构产生的行为，用因果回路识别增强回路、调节回路与延迟。

## 何时使用

- 问题反复出现，单点干预后反弹。
- 多因素相互影响，存在反馈。
- 长期动态问题（拥堵、流失、组织推诿、增长上限）。
- 需要判断"为什么越努力越糟"。

## 何时不使用

- 线性单一因果问题（用 `five-whys`）。
- 需要当期量化决策的问题（用 `mece-decomposition`）。
- 问题只发生一次且无复发迹象。

## 输入

| 参数名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| behavior_over_time | string | 是 | 随时间变化的行为模式 |
| actors | list | 否 | 系统中互相影响的主体 |
| known_levers | list | 否 | 已尝试过的干预及其结果 |

## 输出

- behavior_pattern：行为随时间的变化模式
- causal_loop_diagram：因果回路图（增强 / 调节）
- delays：关键延迟环节
- leverage_points：杠杆点及预期副作用
- boundary_decision：系统边界说明

## 执行步骤

按序执行，不可合并或跳步：

1. 描述行为随时间的变化模式（上升、震荡、停滞、超调）。
2. 定义系统边界：纳入什么、排除什么、为什么。
3. 列出关键变量，标出变量间的因果关系方向。
4. 闭合回路，标注是增强回路还是调节回路。
5. 标出延迟环节与既有干预的反作用。
6. 在回路结构上找杠杆点，而不是在事件层找。
7. 对每个杠杆点写出预期副作用与观测指标。

## 判断规则

| 如果 | 则 |
|---|---|
| 行为呈指数增长或崩塌 | 优先寻找增强回路 |
| 行为趋于稳定或震荡 | 优先寻找调节回路与延迟 |
| 干预短期有效长期失效 | 检查是否挪动了症状而非结构 |
| 出现"越努力越糟" | 检查是否存在目标侵蚀或依赖回路 |
| 边界越画越大、无法收敛 | 收紧边界，只纳入可干预变量 |

## 提问清单

- 这个行为模式持续多久了？以前也发生过吗？
- 哪些变量互相影响？谁影响谁？
- 哪个环节存在时间延迟？
- 过去的干预为什么失效？它改变了结构还是只压住了症状？
- 如果把某个回路断开，行为会怎样？

## 常用工具

- 因果回路图（CLD）
- 存量–流量图
- 系统基模（增长上限、转移负担、目标侵蚀、公地悲剧）
- 时间行为图

## 常见错误

- 把系统边界划得过大，图画不完也无法行动。
- 全部画成线性因果，未闭合回路。
- 忽略延迟，得出"干预无效"的错误结论。
- 只在事件层提对策（如限行），未触及结构。
- 给出杠杆点但不写副作用，导致干预引发新问题。

## 质量检查

输出前逐条核对，未通过的条目标注为待补信息：

- [ ] 已描述行为随时间的变化模式
- [ ] 系统边界有明确取舍理由
- [ ] 至少识别一个增强回路与一个调节回路
- [ ] 延迟环节已标注
- [ ] 杠杆点带副作用与观测指标

## 正例

输入：某城市拥堵。
输出：识别"道路供给增加 → 通行改善 → 自驾需求上升 → 拥堵回升"的调节回路（含建设延迟），以及"公交分担率上升 → 道路占用下降 → 公交准点率上升"的增强回路，给出杠杆点为公交准点率而非新增车道。

## 反例

"拥堵是因为车太多，建议限行。"——只有事件层对策，未触及需求与供给的反馈结构。

## 测试案例

| 输入 | 期望行为 | 禁止行为 |
|---|---|---|
| "交通拥堵怎么解决？" | 识别供需反馈回路与建设延迟 | 只给限行类事件层对策 |
| "跨部门为什么推不动？" | 从激励与流程结构分析 | 归因为"人不配合" |
| "这个政策压下去了，一年后又反弹。" | 检查是否挪动了症状而非结构 | 建议加大执行力度 |

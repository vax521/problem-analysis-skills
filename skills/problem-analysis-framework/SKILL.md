# 问题分析框架（路由与编排）

## 概述

本技能是问题分析框架集合的入口，只做两件事：**按意图路由到原子技能**，以及**约束组合顺序与全局质量检查**。框架的具体协议各自封装在独立的原子技能中，本技能不重复承载。

本技能不替用户做决策，只负责把问题结构化为可检验的形式。

## 子技能清单

| 子技能 | 类型 | 适用问题特征 | 主要输出 |
|---|---|---|---|
| `problem-reframing` | 定义类 | 模糊、无成功标准、直接要方案 | 问题陈述、成功标准、归属 |
| `mece-decomposition` | 分解类 | 复杂、多变量、需分工 | 逻辑树、优先级、分析计划 |
| `five-whys` | 分析类 | 单一因果链、异常、复盘 | 因果链、根因、干预动作 |
| `system-loops` | 分析类 | 反复出现、有反馈、长期动态 | 回路图、延迟、杠杆点 |
| `pyramid-expression` | 表达类 | 需说服、需汇报 | 结论、SCQA 开场、论据 |
| `mckinsey-7step` | 复合类 | 端到端复杂项目 | 七步全交付物 |

## 路由表

| 用户意图 | 路由到 |
|---|---|
| 问题模糊、直接要方案 | `problem-reframing` |
| 需要拆解复杂问题 | `mece-decomposition` |
| 需要找根因（单一因果链） | `five-whys` |
| 需要系统分析（多因素、有反馈） | `system-loops` |
| 需要汇报表达 | `pyramid-expression` |
| 需要完整咨询流程 | `mckinsey-7step` |

同时命中多条时，按"定义 → 分解 → 分析 → 综合 → 表达"的顺序串联执行，不要二选一。更细的选型对照见 `references/framework_index.md`。

## 组合规则

1. 按"定义 → 分解 → 分析 → 综合 → 表达"的顺序组合，不跳级。
2. 单一因果链问题不要引入 `system-loops`，会过度复杂化。
3. 分解维度必须与问题陈述中的目标口径一致，否则退回 `problem-reframing`。
4. 同一问题最多同时使用两个分析类技能（`five-whys` 与 `system-loops`），避免结论互相稀释。
5. `mckinsey-7step` 是容器，内部按顺序调度上述原子技能，不要与原子技能重复调用同一阶段。

## 执行约定

- 每次只加载当前阶段需要的原子技能，不要一次性加载全部。
- 子技能的步骤、判断规则、质量检查以子技能自身为准，本技能不做覆盖。
- 遇到子技能给出的门禁未通过时，停止并补齐，不要继续下一阶段。
- 输出前必须执行本技能的全局质量检查。

## 输出规范

默认输出结构：

1. 问题陈述（一句话，不含解决方案）
2. 结构化分析（按所用原子技能的输出字段组织）
3. 结论与优先级
4. 待确认信息（缺失的输入项）

分析过程与最终结论分开展示，避免把推理链混进结论段。

## 全局质量检查

无论路由到哪个原子技能，输出前必须核对：

- [ ] 问题陈述中不含解决方案
- [ ] 每个问题都有明确的成功标准
- [ ] 主要利益相关者已识别
- [ ] 边界（含什么、不含什么）已声明
- [ ] 分组满足 MECE（不重叠、不遗漏）
- [ ] 结论先行，且每个支撑论点都能回溯到结论

# 麦肯锡七步解决（mckinsey_7step）

## 一句话定义

端到端解决复杂问题的七步流程，内部调度多个原子技能完成各阶段工作。

## 何时使用

- 问题复杂且需要完整交付（诊断报告、战略方案、转型计划）。
- 需要跨多人分工的长期项目。
- 用户明确要求"按咨询流程做一遍"。

## 何时不使用

- 只需单点分析（直接调用对应原子技能，不必套七步）。
- 时间预算极短的快速判断。

## 输入

| 参数名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| initial_problem | string | 是 | 用户原始问题 |
| constraints | list | 否 | 时间、资源、权限约束 |
| decision_maker | string | 否 | 最终决策人 |

## 输出

| 步骤 | 交付物 |
|---|---|
| 1 定义问题 | 问题陈述、成功标准、边界 |
| 2 分解问题 | 逻辑树、MECE 检查 |
| 3 优先排序 | 排序后的子问题清单 |
| 4 工作计划 | 分工、时间表、数据需求 |
| 5 关键分析 | 各子问题结论与证据 |
| 6 综合结论 | 结论、优先级、取舍理由 |
| 7 沟通表达 | 汇报结构、开场、预判反驳 |

## 执行步骤与内部调度

按序执行，每一步完成后核对门禁再进入下一步：

1. 定义问题 → 调用 `problem-reframing`。
2. 分解问题 → 调用 `mece-decomposition`。
3. 优先排序 → 调用 `mece-decomposition` 的 ICE 排序。
4. 工作计划 → 为保留子问题分配责任人与数据来源。
5. 关键分析 → 因果类用 `five-whys`，动态类用 `system-loops`。
6. 综合结论 → 汇总并给出优先级与取舍理由。
7. 沟通表达 → 调用 `pyramid-expression`。

## 步间门禁

| 如果 | 则 |
|---|---|
| 第 1 步未产出可验证成功标准 | 不进入第 2 步 |
| 某子问题数据不可得 | 在第 3 步就被排除，不带入第 5 步 |
| 第 5 步结论与假设相反 | 回到第 2 步检查分解是否遗漏 |
| 第 6 步出现多个并列结论 | 追加一轮 ICE 排序或明确取舍标准 |
| 第 5 步发现问题是动态反馈型 | 切换为 `system-loops`，不要硬套因果链 |

## 提问清单

- 每一步的交付物是什么？谁来验收？
- 假设是什么？哪一步验证它？
- 如果关键假设被推翻，哪一步需要重做？
- 最终决策人最关心哪一项？

## 常用工具

- 逻辑树、议题树
- 假设驱动分析
- 鹰眼分析（先看全局再钻细节）
- 3C / 五力 / 7S
- 金字塔原理

## 常见错误

- 跳过第 1 步直接分解，导致目标漂移。
- 分解后对所有子项平均用力，不做优先级。
- 分析做了很多，综合阶段只罗列不回结论。
- 把过程当作成果交付，决策人看不到行动项。
- 把七步当形式，逐步交付物缺失却继续推进。

## 质量检查

输出前逐条核对，未通过的条目标注为待补信息：

- [ ] 七步各有明确交付物
- [ ] 第 1 步有成功标准
- [ ] 第 3 步有明确舍弃项
- [ ] 每个关键结论有证据
- [ ] 最终输出结论先行且含行动项

## 正例

输入："我们的新品增长停了，怎么办？"
输出：先重构为"新品上架 6 个月后 MAU 增速由 20% 降至 2%"，逻辑树拆为"新客获取、老客留存、客单价"，ICE 排序后保留"老客留存"，用 5Why 找到首次购买后 7 日无核心动作的断点，综合给出优先级与金字塔式汇报结构。

## 反例

直接跳到"关键分析"，做了大量数据切片，最后给出五十页数据而无结论与行动项。

## 测试案例

| 输入 | 期望行为 | 禁止行为 |
|---|---|---|
| "新品增长停了，怎么办？" | 七步各有交付物，逐级调度原子技能 | 跳到分析步，只给数据 |
| "没有数据。" | 在排序步排除不可得项 | 带着不可得数据进入分析 |
| "帮我快速判断一下。" | 直接调用单个原子技能，不套七步 | 强行跑完七步 |
